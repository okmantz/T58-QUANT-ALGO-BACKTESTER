Deploy Live

This one stays desktop-only -- on purpose, not as an oversight.

⚠ This connects to real, funded accounts and trades real money. Unlike every other gap between this web app and the desktop app, this isn't just "hasn't been built yet" -- there are two separate reasons it shouldn't be built the same way here.

Reason 1: the same platform constraint as Forward Test

The desktop app's Deploy Live tab connects the same way its Forward Test / Live Demo Test tab does -- via the MetaTrader5 Python package, which only works on Windows, and only against an MT5 terminal actually installed and logged in on that same machine. There's no web equivalent of "the MT5 terminal on your desk" to connect to from a phone or browser -- see the Forward Test page for the full explanation, since it's the identical underlying limitation.

Reason 2: this server has no login, and Deploy Live handles real credentials

The desktop app stores your prop-firm login via your OS's secure credential store specifically because it's a real broker password. This web server, as configured, has no authentication at all and listens on every network interface -- anyone on the same network (or further, if a port is ever forwarded) could reach it. Building live-credential entry and real-order-placement on top of that would be a serious step backward in safety, independent of the MT5 platform issue above. This isn't a "not implemented yet" gap to close quickly -- it needs a real login system in front of this server first, which is a separate project from anything else in this patch.

What this means practically

  • Use the T58-Quant-Algo-Backtester.exe (or python -m app.main) on Windows for live prop-firm deployment -- that tab works exactly as before, with the same warnings it's always had.
  • Everything else in this app -- backtesting, Full Pipeline, Search Lab, Speed Run, Evolution Lab, Generate Strategies, the Strategy Library -- works identically whether you're on the desktop app or this web app.

If real web-based live deployment matters to you later

The honest options, if this becomes a priority:

  • Leave it desktop-only permanently (simplest, no new moving parts, no new attack surface).
  • Add real authentication (a login, not just "the app is on my LAN") to this server as a prerequisite, then build a small always-on Windows relay service (running wherever a real MT5 terminal lives) that this web app talks to over the network instead of importing the MT5 package directly -- a real project in its own right, and one worth getting a second pair of eyes on given it touches real money, not a quick port.
