Test it properly

The full check: baseline → preflight → walk-forward-aware search → re-validated Monte Carlo → out-of-sample → holdout → a verdict on the evidence ladder (Reject → Lead → Forward-Test Candidate → Evaluate → Funded) alongside the REJECT / LEAD / FORWARD-TEST CANDIDATE read. This is the only run allowed to call a strategy FORWARD-TEST CANDIDATE. It is the slowest thing this app runs — expect it to take a while on a full dataset.

Search
How the optimiser looks for better settings. Every candidate is scored on out-of-sample data chained across folds, so a bigger search finds more — and is penalised for it in the final verdict.
What to optimize
The default ranks candidates on their edge (lower bound of mean R per trade); pass odds size the account later. Not trading a prop-firm evaluation? Pick “Long-Term Net Profit”.
All three score candidates identically — only how the next one is picked differs. TPE / CMA-ES need the optuna / cma packages.
Search size
Candidates per generation.
Rounds of breeding. Population × generations = how many settings are tried.
Quick simulations used only to rank candidates.
Walk-forward windows
How many train/test slices the history is cut into.
Rolling forgets old data; anchored always trains from the start.

Confidence & held-back data
How much evidence the final verdict is built on. More simulations tighten the odds; the holdout is data the search never sees.
