4. Quick Optimize settings

Reuses the walk-forward-aware GA (same engine as Full Pipeline's search step) for a single before/after comparison. Lighter than Full Pipeline -- no OOS holdout check or significance gate -- so a result that improves here is saved to the Strategy Library tagged "draft", not higher.

Not trading a prop-firm evaluation? Pick "Long-Term Net Profit" -- it scores candidates purely on total P&L and ignores prop-firm drawdown/payout rules entirely.

All three run the exact same chained out-of-sample scoring per candidate -- only how the next configuration to try is chosen differs. TPE/CMA-ES need the optuna / cma packages on the server; you'll get a clear error here if one isn't installed.

Off by default. This setting is NOT saved with the optimized strategy -- if you later run this strategy through Full Pipeline, its own "Enable adaptive, limit-aware position sizing" checkbox (off by default there too) needs to match whatever you choose here, or the two results are not comparable.

Off by default -- unchanged, fully in-sample behavior. When checked, the LAST fraction of the dataset below is carved off before the baseline/search run at all, and the winning configuration is backtested against it once, purely to report a less-than-100%-circular number. This is NOT the same as Full Pipeline's own holdout check: there's no walk-forward OOS-fold re-verification and no ICIR/Bonferroni re-check of the holdout segment itself. Every Quick Optimize result -- with or without this on -- is still labeled "NOT OOS VALIDATED"; run Full Pipeline for that.

5. Timeframes to test (optional)

Leave blank to optimize only against the loaded data's own native bar spacing, as before. Fill in a list (e.g. "5m, 15m, 30m, 1h, 4h") and the GA above runs independently once per timeframe -- the dataset gets resampled to each one -- and whichever timeframe's optimized result has the higher eval-pass probability (win rate as the tiebreaker) is what gets saved to the Strategy Library, with that winning timeframe stamped onto it (manual/JSON strategies only) so it keeps trading on that bar size later. The job page shows every timeframe's own numbers side by side.
