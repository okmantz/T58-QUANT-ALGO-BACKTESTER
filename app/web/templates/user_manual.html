Quick start

The whole app in five steps

For anyone in a hurry -- if any of these words don't mean anything yet, the sections below explain each one in plain terms.

  1. Market Data (Test) -- import a CSV, or fetch data with a free Alpaca key, on the Run & Report page.
  2. Strategy Builder (Create) -- pick Manual / Python / PineScript / MQL5 and set it up, also on Run & Report.
  3. Prop-Firm Rules & Risk (Test) -- enter your prop firm's account size, targets, drawdown rules, and per-trade risk (defaults are fine to start).
  4. Full Pipeline (Optimize) -- go to Full Pipeline, click Run, and read the READY / MARGINAL / NOT READY verdict.
  5. Deploy -- once you're confident, Deploy Live or Forward Test (MT5) first if you want a real-market dry run.
That's it. Everything under Optimize, Validate, and Champion in the sidebar beyond Full Pipeline is optional extra tooling for later -- you don't need it for a first pass.
① Create

Building or generating a strategy

Everything under Create is a different way to get a strategy into the Strategy Library so the rest of the app can test it.

  • Strategy Builder -- the Manual visual builder (indicators + entry/exit rules, no code), or paste/upload Python, PineScript, or MQL5. Every strategy type can be loaded from, and saved to, the Strategy Library from this same page's "Load a saved strategy" dropdown.
  • Speed Run -- the fastest way to screen a batch of manual strategy families against your data before committing to deeper optimization.
  • Generate Strategies (AI) -- describe a strategy idea in plain English; an AI model (local Ollama) turns it into a runnable Manual config.
  • Research Agent -- a tool-calling AI agent that can run backtests, Monte Carlo, and walk-forward checks on your behalf and report back what it found.
  • Research Loop -- an unattended background loop that keeps generating and screening candidate strategies over a long run.
  • Evolution Lab also belongs conceptually here (it creates brand-new strategies from scratch via genetic search) but is grouped under Optimize below since that's where it lives in the sidebar.
② Test

Running one strategy against your data

The core backtest loop: pick a strategy, pick your market data and rules, run it, read the report.

  • Run & Report -- the main page: strategy, market data, prop-firm rules, and risk/execution settings all live here, plus the RUN button and the resulting trade-by-trade report.
  • Payout Probability -- Monte Carlo resampling of your backtest's trades to estimate the probability of passing an evaluation and of reaching a first payout, not just a single historical outcome.
Market data, prop-firm rules, and risk settings you enter on this page carry over to every other tool in the app (Optimize, Validate, etc.) for that session -- you only set them up once.
③ Optimize

Tuning or searching for a better strategy

Once a strategy runs cleanly on Test, everything here helps find better parameters -- or better strategies entirely.

  • Overview / picker -- if you're not sure which optimize tool to reach for, start here.
  • Iterative Refinement -- a walk-forward-aware genetic algorithm that tunes one strategy's existing parameters.
  • Search Lab / multi-instrument -- generates and screens candidates across every registered strategy family (47 as of this update) in three stages: a cheap pre-filter, GA refinement, then a strict validation gate (Monte Carlo, walk-forward, robustness).
  • Evolution Lab (GA) / multi-instrument -- an open-ended genetic search that creates, mutates, and re-tests candidates generation after generation, keeping a knowledge graph of what's worked. Set an Optimization goal (balanced, eval pass rate, first payout, net profit, robustness, or custom weights) on the start form to tell it what to actually rank candidates by -- both the single- and multi-instrument pages support this.
  • Full Pipeline -- the recommended one-button path: runs a strategy through every validation stage at once and gives a single READY / MARGINAL / NOT READY verdict.
  • Quick Optimize -- a faster, lighter version of Iterative Refinement for a quick pass.
  • Multi-Objective -- optimizes for several competing goals at once (e.g. drawdown vs. net profit) and shows the trade-off frontier instead of a single "best" answer.
Evolution Lab and Search Lab auto-save promising results to the Strategy Library, tagged evolution-lab -- filter the library's tag dropdown on the Run & Report page to see just those, with their fitness score / eval-pass % / payout % shown right in the picker.
④ Validate

Deeper robustness checks (optional)

Everything here is optional and can be safely skipped on a first pass -- Full Pipeline already runs a reasonable validation gate. Reach for these when you want to stress-test a strategy further before committing real capital.

  • Overview / checklist -- a running checklist of what's been validated for your current strategy.
  • Walk-Forward Opt -- re-optimizes on a rolling in-sample window and tests on the out-of-sample window that follows, repeated across the whole dataset.
  • Walk-Forward GA -- the same idea, using a genetic algorithm for each fold's in-sample optimization instead of a grid search.
  • CPCV / PBO -- Combinatorial Purged Cross-Validation and Probability of Backtest Overfitting -- the most rigorous (and most expensive) overfitting check in the app.
  • Sensitivity -- how much a strategy's results change with small perturbations to its own parameters (a fragile strategy is a red flag even if its base-case result looks good).
  • Regime Survival Matrix -- breaks results down by market regime (trending/ranging, high/low volatility) instead of one blended number.
  • Monte Carlo -- same tool listed under Test above; it's cross-listed here too since it's also a validation check.
⑤ Champion

Combining multiple strategies

Once you have more than one validated strategy, these tools help you combine or compare them instead of running just one at a time.

  • Multi-Asset Portfolio -- runs and combines strategies across several instruments at once, with portfolio-level risk sizing.
  • Multi-Strategy Ensemble -- combines several strategies' signals on the same instrument into one blended equity curve.
  • Family Diversity -- shows which strategy families a Search Lab or Evolution Lab run actually found winners in, so you're not unknowingly running five near-identical variants of the same underlying edge.
⑥ Deployment

Going live

  • Forward Test (MT5) -- runs a validated strategy against live, real-time MetaTrader 5 data without risking capital -- a real-market dry run before Deploy Live.
  • Deploy Live -- connects a validated strategy to a live account. Real capital -- read every warning on that page first.
  • Monitor (Live Market) -- a live dashboard for a strategy already running, so you can watch it without leaving the app.
Deploy Live trades with real money. Everything above it in this manual -- especially Full Pipeline and, ideally, at least one Validate check -- exists so you reach this step with evidence, not a hunch.

Decision guide

What to do depending on your results

Everything above is the order to click through the FIRST time. This section is different: it's organized by decision point, not by tab, for when you already have a real result in front of you and want to know what it means. Every branch below also prints live, as a green "Next step:" note, right after the run that produced it (see app.orchestration.pipeline_guide in the codebase -- the same logic drives both those live messages and this reference section, so they can never disagree with each other).

After your very first backtest (Run & Report)

  • Zero trades generated — don't touch risk or prop rules yet. Check the strategy's own entry logic first: too strict a condition, a timeframe mismatch, or (Manual Builder) an indicator combination that never actually fires are the usual causes.
  • Fewer than ~20 trades — too few for Monte Carlo or a prop simulation to say much with confidence. Try a longer data range, a lower timeframe, or a looser entry condition before trusting any pass-probability number from this run.
  • Profit factor below 1.0 — this version loses money over this data. Don't chase it with Full Pipeline yet — adjust it by hand, or let Search Lab / Evolution Lab explore variations and other families automatically.
  • Max drawdown above ~40% — severe for most prop-firm limits (many cap overall drawdown around 8-10%). Tighten the stop-loss or lower risk per trade on Risk & Execution before moving on, even if the profit factor looks fine.
  • Failed the prop-firm simulation despite decent trade stats — check the failure reason shown in the report. Daily loss limit and max drawdown are the two most common single-run killers — re-check that Prop-Firm Rules actually matches your real firm's terms.
  • None of the above — reasonable first result. Check the eval-pass / first-payout probabilities the same run just computed, then either promote to Full Pipeline directly, or try Search Lab / Evolution Lab first to see if a nearby variant does better.

Choosing where to start creating a strategy

  • Already have a specific setup in mind (rule-based, an MS-LSD-style structure/liquidity/ order-block idea, or existing Python/PineScript/MQL5 source) → Manual Builder or upload it directly. Search Lab and Evolution Lab are for when you DON'T have a specific idea — skip them for now and come back later to see if a variant beats your own design.
  • No specific idea yet → Search Lab (bounded, three-stage, faster) or Evolution Lab (open-ended, meant to run for hours unattended) are both better starting points than a blank Manual Builder. Use Search Lab for a quick first pass; use Evolution Lab if you want to leave it running and come back to a leaderboard.

Search Lab / Evolution Lab leaderboard, once you have one

  • Nothing survived Stage 1 at all (Search Lab) → try a wider family selection, a higher max-candidates count, or looser Stage 1 filters (min trades / min profit factor).
  • Some candidates made it partway but none passed every gate → promote the top one and run it through Full Pipeline anyway, or widen the search and try again.
  • A clear champion / strong leaderboard → click PROMOTE, then run it through Full Pipeline for a re-validated, walk-forward-optimized verdict before considering a live evaluation.
Evolution Lab's own leaderboard "eval pass probability" is scored IN-SAMPLE, against the same data the GA searched with — it will usually look better than an honest out-of-sample number. Check the CPCV OOS pass-probability column next to it; a big gap between the two means overfitting, not a strong strategy. Full Pipeline re-checks this properly.

Full Pipeline verdict

  • READY → your strongest evidence yet, but still a backtest. Consider a short Forward Test (MT5) or paper trading before risking real capital on a prop-firm evaluation.
  • MARGINAL → not clearly ready or clearly dead. Try Quick Optimize on it, or adjust risk settings (position size, daily-loss limit) and re-run Full Pipeline. Don't take it live as-is.
  • NOT READY → doesn't hold up under re-validation. Go back to Evolution Lab or Search Lab for a different candidate rather than trying to rescue this one.

Forward Test (MT5) results

  • Any errors during the session → almost always broker/connection/symbol-mapping issues, not the strategy. Resolve them and run another session — a session with unresolved errors proves nothing either way.
  • Zero trades triggered → can be entirely normal for a low-frequency strategy over a short window. Run a longer session before concluding anything, especially if the backtest also traded infrequently.
  • Live fills diverged from what the backtest predicted → check slippage/spread/commission assumptions on Risk & Execution against what the broker actually gave you, then re-run Full Pipeline with updated execution costs.
  • Ran cleanly and roughly matched the backtest → this is your strongest evidence yet. Deploy Live is reasonable from here, starting at reduced size if your firm allows it, with Monitor (Live Market) open to watch the first stretch.

Troubleshooting things that have gone wrong before

  • Evolution Lab winners pass on its own leaderboard but fail almost every Full Pipeline re-check → check that Evolution Lab's own "Prop account & risk" fields (right there on that page) actually match your real numbers. They build the exact same RiskConfig/PropRules Full Pipeline uses, so if either was left at the generic $100k / 8% / 5% / 10% / 1%-risk defaults while you filled in real numbers elsewhere, Evolution Lab was searching under different rules than Full Pipeline checks against — not a bug in either tool, a mismatch between them.
  • Search Lab or Evolution Lab appears to stall partway through a batch → STOP and START again; both now detect a genuinely hung worker and recover automatically rather than waiting forever, but a manual restart is always safe if you don't want to wait it out.
  • Evolution Lab keeps returning the same 2-3 strategy families every run → click VIEW FAMILY HEALTH — a family that's had many tests with zero successes gets deprioritized, with a floor so it's never fully excluded. RESET FAMILY HEALTH if you've since fixed a bug that was unfairly tanking a family's record.
